# План: импорт событий и проектов с набором, сбор команд под события

Статус: план от 13 октября 2026 (ревизия 3 после двух раундов проверки отделом Codex), не реализован. Связан с разделом «Следующий этап после редизайна: импорт» в [product-plan.md](product-plan.md); правила сборщиков — [discovery.md](discovery.md).

## Идея

Krug не копирует чужие площадки, а собирает в одном месте события и объявления о наборе из **заранее проверенных источников** и даёт то, чего у них нет: **найти или собрать команду под конкретное событие**. Регистрация, правила и подача работ остаются на сайте организатора: Krug показывает краткую карточку, ссылку на первоисточник и командную часть. «Проверенный источник» означает проверенный способ получения данных, а не гарантию качества каждого объявления.

## Что уже есть в коде (проверено 13.10.2026, HEAD `9e0e693`)

- `Event` поддерживает внешние записи: `origin = external`, `source_name`, `source_external_id`, `source_url`, `canonical_url`; у внешних `owner_id` может быть пустым (`backend/models.py:528-579`). Уникальны независимо `(source_name, source_external_id)` и `canonical_url` (`models.py:539-540`); индекс по времени публичных событий есть (`models.py:541`). Поля организатора нет.
- Внешнее событие сейчас создаёт только пользователь вручную: владелец обязателен, `source_external_id` API не принимает, модерации нет (`routes/events.py:116-131`). `canonical_event_url` сохраняет query (`routes/events.py:30-34`).
- Команды привязываются к событию (`teams.event_id`, много команд на событие), есть роли, заявки, приём владельцем, перенос состава в проект (`routes/teams.py`); на странице события уже есть блок команд и ссылки «Создать команду» / «Найти команду» (`frontend/platform.js:432-435`).
- Интерес к событию: `event_engagements` (saved / interested / interested_visible); форма говорит «Планирую участвовать» и «Показать мой интерес другим» (`platform.js:283`). Публичный список уже есть: `GET /events/{slug}/interested` — username, имя, bio, аватар (`routes/events.py:204-222`), без навыков и без проверки профиля сотрудничества. Правила видимости профиля сотрудничества: discoverable, active, задано намерение, обновлён не старше 30 дней (`routes/collaboration.py:30-33`).
- Модерация внешних проектов (`ExternalSubmission` → `Project`, `models.py:344-359`, `routes/collaboration.py:402-449`) — образец, но связана именно с проектами.
- Шаблон сборщика у проектов: dataclass, upsert по `(source_name, source_external_id)` только для неклеймленных внешних, advisory lock, остановка на 403/429, предел ответа, пометка устаревших (`backend/github_import.py`, `gitlab_import.py`); один beat на развёртывание (`docs/development.md:71`).
- CSP: `img-src 'self' blob:` — чужие картинки не загрузятся. Главная получает 3 активных и 3 ближайших события и ограниченные выборки для календаря (`frontend/home.js:73-76`).
- Ошибка отображения: время события показывается в часовом поясе браузера рядом с названием пояса события (`platform.js:436`).

Пробелы команд, которые закрываются **до** включения импорта: привязка к прошедшему/отменённому событию разрешена; редактор команды предлагает только 50 ближайших событий, и переход «Создать команду» с события вне списка теряет привязку; владелец принимает заявку без повторной проверки, что команда набирает и роль открыта.

Перед включением каждого источника: проверить robots.txt, условия (ссылка и выдержка с датой — в `docs/discovery.md`), контракт ответа; robots.txt не считается разрешением на перепубликацию, поэтому храним минимум (название, даты, организатор, короткое описание, ссылка) и указываем источник. Процедура удаления: по обращению организатора/площадки запись скрывается администратором, источник при необходимости выключается.

## Архитектура

### Данные (одна миграция)

- `events`: `last_verified_at` (когда сборщик последний раз подтвердил запись), `hidden_at` и `hidden_by_id` (скрыто модератором), `source_organizer` (строка), `source_participants` (целое, CHECK ≥ 0). Отмена ставится только по явному сигналу источника и не перезаписывается расчётом по датам.
- Импортированное = `origin = external AND owner_id IS NULL`; для таких CHECK: `source_name` и `source_external_id` заданы. Пользовательские внешние события (с владельцем) не меняются.
- `event_engagements`: `looking_for_team` (bool) — отдельное согласие «ищу команду», независимое от «планирую участвовать»; CHECK `NOT looking_for_team OR interested`. Снятие «планирую участвовать» сбрасывает и `looking_for_team`, и `interested_visible` (сейчас `routes/events.py:183-189` сбрасывает только видимость). Существующим пользователям флаг не выставляется автоматически.
- `event_suggestions` (этап 4): url, комментарий, автор, статус (pending/approved/rejected), кто и когда решил, ссылка на созданное событие. Не переиспользуем `ExternalSubmission` — она про проекты.
- Идентичность определяется `(source_name, source_external_id)`, не slug. Slug — `devpost-<id>`, `itch-<jam-slug>`, обрезка до 100 символов (`platform_schemas.py:12`); если slug занят (например, пользователь заранее создал `devpost-123`), добавляется суффикс `-2`, `-3`… в пределах 100 символов, конфликт не останавливает импорт (тест обязателен); для одобренных предложений `source_name = manual`, `source_external_id` = sha256 нормализованного URL. `participation_url` = страница события у источника; `source_url` = страница источника.
- Единое правило публичности события (функция фильтра): `visibility = public AND hidden_at IS NULL`; применяется к списку, деталям, поиску, `interested`, share-страницам, маршруту обложки (`routes/media.py:125-138`, сейчас проверяет только `visibility`) и выбору события в редакторе команды. Существующий доступ владельца к своим черновикам сохраняется (`routes/platform_common.py:37`). Скрытые события исключаются всегда; параметр `include_hidden` учитывается только для администратора. Скрытое событие видят администратор и участники уже привязанных команд (связь команд не рвётся, показывается пометка «Событие скрыто»).

### Сборщик

- Пакет `backend/event_import/`: `ImportedEvent` (dataclass с именованными полями), `devpost.py`, `itch.py`, `fetch.py` (общий безопасный HTTP), `store.py`.
- Сеть (`fetch.py`): только домены из списка адаптеров (allowlist; произвольные URL сервер **не скачивает** в v1 — это закрывает SSRF); HTTPS, порт 443; не больше 3 редиректов и только внутри того же домена; таймаут на запрос 15 с и общий бюджет запуска источника 120 с; предел ответа проверяется при чтении потока (JSON 512 КиБ, HTML 2 МиБ), без автоматического распаковывания сверх предела; `User-Agent` с названием Krug и адресом проекта; пауза ≥5 с между запросами к одному источнику; 403/429 — источник останавливается до следующего запуска (Retry-After ≤30 с — один повтор); robots.txt через `urllib.robotparser`, кэш на сутки; если robots.txt недоступен (403/429/5xx/таймаут) — источник в этот запуск не опрашивается.
- Разбор: только данные, без выполнения скриптов; JSON-LD читается как JSON без загрузки `@context` и вложенных ресурсов. Нормализация проверяет все поля: длины, перечисления (тип, формат), HTTP(S)-ссылки через `safe_http_url`, неотрицательные числа, IANA-пояс. Без `starts_at` или однозначного пояса запись не создаётся (itch.io даёт UTC — пояс `UTC`; Devpost — из JSON-LD; смещение без пояса не превращается в выдуманный пояс). Дедлайн из Devpost — это приём работ, подпись «Приём работ до».
- Описание: короткое (≤500 символов), чистый текст; полный текст не копируем.
- `store_events`: каждая запись в своём savepoint; upsert по `(source_name, source_external_id)` только для строк с `owner_id IS NULL AND hidden_at IS NULL`; конфликт `canonical_url` ловится ограничением БД (без гонки «проверил — вставил»): если URL занят событием пользователя или другим импортом — запись пропускается и логируется, остальной источник продолжается. Нормализация URL — правила конкретного источника (например, убрать трекинг-параметры только там, где формат известен).
- Отсутствие записи в ограниченной выборке **не** означает отмену: такая запись просто не получает новый `last_verified_at`; если он старше 7 дней, интерфейс показывает «данные давно не обновлялись». `cancelled` — только по явному статусу источника. Статусы `scheduled/active/ended` у импортированных событий пересчитывает отдельная задача Celery раз в час по датам — независимо от того, попала ли запись в выборку и включён ли источник (API фильтрует сохранённый `Event.status`, `routes/events.py:88-100`); явная отмена не перезаписывается. Если `ends_at` нет, событие считается идущим 24 часа от начала, интерфейс пишет «окончание не указано». Проверки порядка дат (`platform_schemas.py:157-162`) сохраняются. Источник `manual` сборщиком не обходится.
- Celery: задача `refresh-external-events` каждые 6 часов с `expires`, отдельный транзакционный advisory lock (`731945, 3`), удерживаемый до завершения записи, как в `github_import.py:130-138`; ручное создание и одобрение предложений полагаются на ограничения БД и savepoint, а не на lock. По умолчанию выключено (`EVENT_SOURCES=` пусто), включается на экземпляре явно.

### API

- `GET /events`: фильтры `origin=native|external`, `source=devpost|itch|manual` (скрытые не попадают никогда, кроме администратора с `include_hidden`); в ответ — `source_organizer`, `source_participants`, `last_verified_at`, `teams_count` (пакетно, одним подзапросом, без N+1).
- `GET /events/{slug}/interested`: параметр `looking_for_team=true`; навыки и намерение добавляются только для пользователей с публичным профилем сотрудничества по правилам `discoverable_profile()`; без email и контактов.
- `PATCH /events/{slug}/engagement` (существующий маршрут состояния, `routes/events.py:225`): поле `looking_for_team`.
- `GET /team-openings` и списки команд: пакетно добавить `event {slug, title}` для команд, привязанных к публичному нескрытому событию (сейчас `OpeningTeam` отдаёт только slug/title/summary, `platform_schemas.py:378-386`, `routes/teams.py:207`) — для подписи «для GMTK Game Jam 2027» без N+1.
- Админ: `POST /admin/events/{id}/hide` / `unhide`; `GET /admin/event-import/status` (последний запуск, число записей, ошибка — по источникам, из журнала/Redis).
- `POST /events/suggest` (этап 4): пользователь предлагает ссылку; сервер её не скачивает; администратор в очереди видит ссылку и вручную заполняет/подтверждает поля (или, если домен входит в allowlist, получает предпросмотр от адаптера) и публикует.

### Команды под событие

- «Собрать команду» на странице события: переход к созданию с привязкой; редактор команды подгружает событие из параметра отдельным запросом, если его нет в списке; гость проходит вход и возвращается к созданию.
- «Ищу команду»: отдельный переключатель с пояснением, кто это увидит; отзывается в один клик.
- Блоки страницы: существующий «Команды на это событие» (сначала набирающие, с открытыми ролями) и новый «Ищут команду» (только `looking_for_team` и публичный профиль сотрудничества; кнопка «Открыть профиль», не «Пригласить»).
- Исправления (этап 0): привязка к событию проверяет статус (`ended/cancelled` нельзя выбрать для новой или изменённой привязки; существующие связи сохраняются); приём заявки в одной транзакции блокирует команду и роль (`FOR UPDATE`) и проверяет, что команда набирает, а роль открыта.

## Отображение

- **Карточки событий** (списки, главная, календарь): чип источника («Devpost», «itch.io»), метка «Внешнее»; обложка — буквенная заглушка цвета события (CSP и приватность); «1 695 участников на itch.io», если есть; «2 команды в Круге», если есть.
- **Страница импортированного события**: шапка события (оранжевая); мета — «Источник: itch.io · данные обновлены 13 октября»; основное действие — «Собрать команду» (цвет события), вторичное — «Регистрация на сайте ↗» (`rel="noopener noreferrer nofollow"`, `target="_blank"`); факты — даты в поясе пользователя и отдельно в поясе события (исправить `platform.js:436`), длительность, формат, организатор, «Приём работ до»; заметка «Регистрация и правила — на сайте организатора. Krug помогает собрать команду». Состояния: прошедшее, отменённое, давно не обновлялось, скрытое (для участников команд).
- **Список событий**: «Все / События Круга / Внешние», чипы источников, тип (хакатон / геймджем / встреча); состояния загрузки, ошибки, пусто.
- **Главная**: сервер отдаёт отдельные выборки native и external; «Сейчас и скоро» — не больше одного внешнего события из трёх, приоритет внешним, где есть команды (`teams_count`); календарь — внешние с чипом источника; «Ищут людей» подписывает команды «для GMTK Game Jam 2027».
- Пустое состояние: «Под это событие ещё нет команд — соберите первую».
- Проверки интерфейса: клавиатура и фокус, reduced-motion, 320–3840 px, RU/EN с правильными формами множественного числа, обе темы, все данные источника — только через экранирующий `html` (никаких `raw`/`innerHTML`/CSS из данных).

## Этапы

0. **Команды**: три исправления выше + тесты (привязка к прошедшему событию, предзаполнение события вне списка, гонка приёма заявки и закрытия роли).
1. **Первый законченный срез — Devpost**: миграция, `fetch.py`, `ImportedEvent`, `store_events`, адаптер Devpost, Celery-задача, единое правило публичности, фильтры API и `teams_count`, чип/метка/страница импортированного события, существующий блок команд. Тесты на синтетических данных: нормализация и отказ при неполных данных, идемпотентность, защита пользовательских и скрытых событий, конфликт `canonical_url` без отката источника, 403/429/robots недоступен/размер/редиректы вне домена, перекрытие запусков, отсутствие в выборке ≠ отмена, явная отмена не перезаписывается, часовые пояса.
2. **itch.io**: разбор HTML (оба варианта карточки: «Starts in … · Lasts …» и «Submission closes …»); 0 карточек или изменённая разметка = ошибка источника, записи не трогаются; тесты на синтетической разметке той же структуры. Главная и календарь с отдельными выборками.
3. **«Ищу команду»**: поле и согласие, расширение `interested`, блок на странице, отзыв видимости; браузерные сценарии.
4. **Модерация**: скрытие/возврат, статус источников, предложения ссылок пользователями с ручным заполнением.
5. **Проекты, набирающие людей** (обязательная часть исходного объёма): импортируются только **явные объявления о наборе** (ссылка, дата публикации/актуальности, роли/условия, источник), отдельно от проектов — обычный репозиторий или `help-wanted` в issue не считается набором. Людей как участников не импортируем. Кандидаты, требующие выбора пользователя и проверки условий: Reddit r/INAT и r/gameDevClassifieds (официальный API с OAuth-приложением и ограничениями условий), форумы «Team Recruitment» на itch.io (HTML), hh.ru API (официальный, для оплачиваемой работы). Модель — отдельная сущность «внешнее объявление о наборе» со сроком актуальности; отображение — в «Ищут людей» с чипом источника и ссылкой.

Каждый этап — мелкие коммиты, перекрёстная проверка Codex, деплой на `krug-release-check` по обычному порядку (экземпляр включается только для проверки и снова останавливается, пока пользователь не решит иначе).

## Риски

- Недокументированные форматы (Devpost JSON, HTML itch.io) ломаются без предупреждения: адаптер падает громко, данные не трогает.
- Условия площадок меняются: повторная проверка перед включением и при изменении поведения; при запрете источник выключается.
- Объём Devpost велик: фильтр по статусу, лимит записей и страниц, отдельный запрос JSON-LD только для новых/изменённых хакатонов.
- Кросс-дубли (событие на Devpost и на сайте организатора) в v1 ловятся только по `canonical_url`.
- Приватность: людей с площадок не импортируем; «Ищут команду» — только пользователи Krug с явным согласием.
